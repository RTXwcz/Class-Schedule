# v1.5.5 课表自由平移验证

本次按反馈修掉“一次只能横着划或竖着划”的手感问题：课表改成两轴自由平移，并补上惯性滑行。日期为 2026-09-11。

## 问题与原因

旧实现的课表由两个原生滚动容器叠加而成：外层负责纵向、内层负责横向。Compose 的滚动容器各自锁定单一轴向，横向容器先越过触摸阈值就只横着动，纵向先越过就只竖着动，所以手指画斜线时永远只有一个方向跟手。

## 现在的行为

- 手势在父节点以 `PointerEventPass.Initial` 先于滚动容器处理，超过触摸阈值后由同一个手势同时驱动两个 `ScrollState`，手指画到哪里内容就跟到哪里，斜向拖动也不再被拆成两次操作。
- 两个滚动容器保持启用，因此语义滚动（无障碍、`performScrollTo`）和内容钳制仍由它们负责，只是不再参与手势竞争。
- 松手后按手势速度继续惯性滑行：纵向与横向各自按同一时间常数衰减，速度低于 60px/s 停止；新一次触摸立刻取消滑行。
- 惯性用时间积分（`delay` + `System.nanoTime`）而不是帧动画，避免了“帧时钟不可用导致动画完全不执行”的情况，也让滑行距离与刷新率无关。
- 双指捏合缩放不变，另外补上了捏合过程中的平移，可以一边缩放一边定位到别的星期。

## 验证证据

| 检查 | 结果 |
| --- | --- |
| 单元测试 | 从 ASCII 构建路径 `D:\kebiao-build\apk\android` 运行，全部通过 |
| Android 15（API 35，411dp） | UI、数据、MCP、提醒与小组件共 57 项全部通过 |
| Android 7.0（API 24，360dp） | 同一套 57 项全部通过 |
| 自由平移 | 一次斜向拖动后，课程卡片的左边界与上边界同时移动，卡片宽度不变；星期表头只横向移动、时间刻度只纵向移动 |
| 惯性滑行 | 同样 220px 的手势距离，40–60ms 的快速滑动比 500ms 的慢速拖动多滑出 80dp 以上 |
| 旧行为回归 | 单轴滑动、`performScrollTo` 定位、缩放宽档、双指捏合吸附回全览全部保持通过 |
| 实际界面 | 真机（模拟器）日志确认滑行 61 帧、约 1 秒后自然停止，滑动过程中截图内容持续移动 |

## 已知边界

- 惯性滑行按屏幕像素速度衰减，滑到内容边界即停，没有回弹效果。
- 两轴同时滑行时，两轴各自独立衰减，斜向甩动结束后可能先停住一个方向，这是符合直觉的行为。
- 用户的澎湃 OS / Android 17 实体设备仍未直接验证。
