# v1.6.3 作息识别与云端接口验证

本次处理两件事：从课表图片里把「一天几节、每节几点到几点」也读出来；修好 OpenAI 兼容接口的实际可用性。日期为 2026-09-11。

## 从课表读作息

时间轴列（节次号 + 起始时间 + 结束时间）在解析时单独处理：按节次号定位每一行，取该行内的时钟标签作为起止时间，并要求

- 至少 4 节；
- 每节都有起止两个时间，且时间严格递增；
- 节次号从 1 连续编排（缺号会让用户的节次错位，宁可整体不采用）。

复核页顶部会出现「识别到 N 节作息」卡片，点「应用为每日作息」即写入 设置 → 每日作息，课程卡片、提醒与桌面小组件都按新作息计算。

## 云端识别：为什么之前用不了

用真实 key 实测了两个 OpenAI 兼容服务：

| 服务 | 结果 |
| --- | --- |
| `https://api.deepseek.com` + `deepseek-flash` | 支持图片，按字段返回 JSON，正常 |
| `https://direct.abinapi.com` + `Qwen3.8-Flash-Next` | 需走 `/v1/chat/completions`，正常 |
| `https://direct.abinapi.com`（根路径当 API） | 返回的是 New API 控制台网页（HTTP 200 HTML），旧版本会报“响应缺少课程内容” |
| `grok-4.6` | 该 key 返回 403（模型列表里是 grok-4.20 系列），现在会把服务端错误原文显示出来 |

对应修复：

1. 地址只填根地址也能用：自动补 `/v1/chat/completions`；已是完整路径则保持不变。
2. 请求显式 `stream: false`（部分网关默认流式，返回 SSE，App 无法解析）。
3. 非 JSON 响应给出明确提示：地址可能填成了控制台首页。
4. 4xx/5xx 时把服务端 `error.message` 与排查提示一起显示（401 检查 Key、403 模型名/权限、404 地址、429 限流）。
5. 设置页新增「测试连接」：只发一次文本请求，验证地址、Key、模型名是否匹配，不消耗图片识别。
6. 设置页写明模型必须支持图片输入，并给出常用示例。

## 已知边界

- 少数折行标题很长且带重复节次的课程，教师字段可能取到标题的续行，需要在复核页改一笔。
- 时间轴缺行或时间不连续时不会采用作息识别，避免把节次编号改错。
- 云端识别会把图片发送到用户配置的服务；本地 OCR 仍完全离线。
