# v1.7.0 对抗式审查与修复验证

按“对抗式审查不修代码、先报问题”的流程列出的风险，逐条处理并给出证据。日期为 2026-09-11。

## 修复清单

| # | 审查发现 | 处理 |
| --- | --- | --- |
| 1 | 导入复核页只渲染错误、不显示“已追加 N 门”，部分导入后用户以为失败 | 复核页顶部显示导入结果（`ImportExportScreen`） |
| 2 | MCP 在公共 Wi-Fi 上同网段设备可嗅探明文 Token、无速率限制 | 每对端 10 秒 60 次滑动窗口限流（超限 429）、请求体积上限 1 MiB、设置页新增公共网络安全提示 |
| 3 | 数据库迁移无测试覆盖 | 新增 `ScheduleMigrationTest`：用 Room 导出的 schema 建 v3 库，跑 3→4 校验数据与新增列（v1/v2 的 schema JSON 未保留，已在测试注释中说明） |
| 4 | 概览档把冲突课程并成一格，点击只能编辑第一门 | 卡片点击弹出选择列表（`clash-choice-<id>`），选哪门就编辑哪门；单课程卡片仍直接进编辑器 |
| 5 | 云端识别拿不到“应用为每日作息” | 视觉契约改为 `{courses, periods}`，云端也能带回时间轴；两条路径共用同一张作息卡片 |
| 6 | release 缺签名环境变量时静默产未签名包 | 构建期断言：release 任务缺签名环境直接失败，可用 `CLASS_SCHEDULE_ALLOW_UNSIGNED=1` 显式放行（CI 用于编译校验） |
| 7 | CI 不构建 release 变体，R8/资源收缩无回归 | CI 增加 `:app:assembleRelease :app:lintRelease`（带放行变量） |
| 8 | 备份 JSON 的 `schemaVersion` 不校验、`weeks` 字符串形态报错误导、日期不校验 | 新版本备份直接拒绝并提示升级；`weeks` 支持数组与 “1-8,10” 字符串；考试/调休日期非法时报出具体字段 |
| 9 | MCP Token 密文损坏时只在一种异常下自愈 | 解密失败（截断、AEAD、密钥丢失）统一轮换新 Token |
| 10 | 冲突标记只看相邻课程，链式重叠漏标 | `ScheduleResolver` 改为“到目前为止的最大结束节次” |
| 11 | 时间轴节次跳号时整块放弃作息识别 | 只要从 1 开始且严格递增即采用（按位置编号），跳号不再丢弃 |
| 12 | 教师姓“楼”被当成教学楼、标题续行被当成教师 | 地点判定改为“以场馆词结尾”，姓名可含楼/馆/场/室；新增回归测试 |
